## 一句话

修掉「第 5 张开始翻页失灵」这个真 bug，并让复位胶囊自己判断该用黑字还是白字。

## 新增

**复位胶囊自适应配色**

- 胶囊出现的那一刻，量一遍「它身后那一块」的平均亮度，再选配色：
  - 身后偏亮（平均亮度 > 0.58）：95% 白底 + 近黑字 + 15% 黑描边
  - 身后偏暗：77% 黑底 + 近白字 + 24% 白描边 + 琥珀色「复位」
- 采样会把缩放 / 平移 / 旋转的逆变换算进去，放大到 2.6x 时量的是屏幕上真正被胶囊盖住的那块像素，
  而不是照片原始的下边缘
- 只在「开始有变换」时采一次，捏合与平移过程中不重复读像素

## 修复

| 问题 | 根因 | 处理 |
|---|---|---|
| 画廊总数比实际多，翻到第 5 张开始重复、编号也乱 | 会话里的记录用 `content://media/external/images/media/<id>`，目录查询用 `content://media/external/files/<id>`，同一个文件两个字符串。按 uri 去重完全失效，10 张被算成 14 张 | 身份改用**落盘文件名**：去重、选中态、手势 state、缓存 key 全按文件名，uri 只当取图地址 |
| 翻过一页之后手势失灵（再滑不动） | `photoGestures` 的 `pointerInput` key 只有 `aspect`，相邻两张尺寸相同时节点不重建，闭包里还握着**上一张**的 `ZoomState` 和回调，于是拖动写进旧状态、翻页调到旧索引 | key 增加「当前照片身份」，每次换图都重建手势节点 |
| 复位胶囊的黑色文字在暗部照片上看不清 | 白天模式的胶囊底只有 8% 黑、文字近黑，压在暗部（夜景、深色桌面）上对比不足 | 见上方「自适应配色」，两套方案底色都是 77% / 95% 不透明，文字对比始终够 |
| RAW 在画廊里只能用内嵌缩略图 | 目录记录拿不到相机原始名（`orig` 被填成落盘名），与同批 JPG 的配对键对不上 | 配对键改为「文件名末段」（`20261117-0010-PB170519` → `PB170519`），RAW 也能用同批高清 JPG 做代理 |

## 改进

- 相邻页预解码的缓存 key 与主流程统一（RAW 用代理 JPG 的 uri），切过去不再解第二遍
- 同一张照片的 uri 从会话切到目录时保留旧位图，刚收到照片不会白闪一下
- `Pal.overChip` 系列不再用于胶囊（浅色主题下过淡），仅保留给其他浮层

## 已知问题

- 双指捏合 / 旋转仍需手动确认（adb 无法模拟多指）
- 画面明暗高度交织时（大面积高光 + 深阴影），采样平均值可能落在中间地带，
  会选到深色一套；两套底色都不透明，最差情况仍可读，只是不如同调时好看
- 视频（MOV）封面取首帧，未按容器旋转矩阵二次校正
