## 一句话

把 OM Capture 的「连同一 WiFi 自动收图」搬到手机上——连上相机就常驻监听，一按快门自动落盘。

## 新增

**协议栈（`PtpIp.kt` / `OmCamera.kt`）**

- PTP/IP 握手按抓包结论实现：先 `GET :1900/DeviceDescription.xml`（UPnP）否则相机不亮 PC 连接图标
- GUID 必须是相机白名单里的客户端标识（具体值属设备凭据，不随仓库发布），随机 GUID 会被回 Init Failed
- `OpenSession` 事务号必须为 **0**；事件通道必须在它之前建立
- 事件通道 `0xc10d` 新文件推送驱动下载；`0x94dd` 取文件名与大小
- `0x94de` **5 个参数**（句柄, 偏移, 长度, 0, 0）、3 MB/块分块读取
- `0x94be` 必须带上行数据阶段 8 字节 `(1, 句柄)`，结束包类型为 **0x0c**（非标准 0x0b）
- 视频事件到达时文件仍在刷盘，`0x94de` 回 `0x2019` → 等 2 秒重试

**发现与连接（`Discovery.kt`）**

- SSDP 组播发现 + 全网段扫 15740 端口
- 支持手动填 IP（热点场景下相机 IP 不固定）

**保存（`MediaSaver.kt`）**

- 写入 `DCIM/OM Phone`，`IS_PENDING` 占位防半截文件
- 文件名与相机一致，类型按事件 fourcc 判定：`GPJ.`→JPG、`FRO.`→ORF、`VOM.`→MOV

**常驻与筛选（`CaptureService.kt` / `AppBus.kt`）**

- 前台服务 + 唤醒锁 + 常驻通知，锁屏也能持续收图
- 断线后 5–20 秒自动重连
- 卡槽 1 / 卡槽 2 × RAW / JPEG / MOV 三类独立勾选，未勾选的类型不下载

**界面（`MainActivity.kt`）**

- 竖屏控制面板：连接、格式勾选、传输进度、已收数量与总大小
- 横屏基础预览，可看已收到的照片

**测试**

- `PtpWireTest` 用假相机服务器做线级校验：Init 38 字节、`OpenSession` TID=0、`0x94de` 38 字节 5 参数、`0x94be` 上行 8 字节 + `0x0c` 结束包，3 项全通过
