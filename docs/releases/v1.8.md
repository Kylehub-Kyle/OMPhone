## 一句话

不碰取图链路，专修「第一次用的人会踩的三个坑」：配置错误被网络错误盖住、长提示被省略号吃掉、
相机地址被记住导致连到旧地址。

## 改进

- **打开即自动发现**：进入主界面就开始 SSDP 组播 + /24 网段扫 15740，找到相机后直接填进地址框；
  找不到就静默留空，不弹红色横幅打扰
- **每次连接前重新发现**：相机开热点 / 换网络后地址会变，拿上次的地址去连是「偶发连不上」的主因。
  现在点「连接」先发现再连；只有发现失败时才用输入框里手填的地址兜底，两者都没有就给出可操作提示
- **相机地址不再持久化**：删掉 `Preferences` 里的 `last_ip`，冷启动永远是「空 → 发现 → 填入」，
  不会再出现"打开就是上次那个连不上的 IP"

## 修复

| 问题 | 根因 | 处理 |
|---|---|---|
| GUID 为空时只看到 `EHOSTUNREACH` / 超时，看不到配置错 | `clientGuid()` 在 `cmd.connect()` 之后才调用，网络错误先抛出 | 提到 `runSession()` 第一行，先校验配置再碰网络 |
| 短 GUID 能通过校验 | 只做 `hexToBytes`，没校验长度——`"abc123"` 本身是合法十六进制，会被当成 3 字节 GUID 发给相机 | 强制 32 位且逐字符 hex 校验，报出当前长度 |
| 提示被省略号截断（`未配置客户端 GUID：在 l…`） | 顶部状态胶囊 `maxLines = 1` + `Ellipsis`，宽度还被标题挤压 | 新增 `UiState.error`，用可换行的横幅单独展示；超过三行点击弹窗看全文；胶囊只留"连接失败"这类短状态 |
| 空 GUID 时无限重连刷通知 | `supervise` 循环无条件「等 5~20s 再连」 | 配置类异常标记 `fatal`，服务直接停下，等用户改配置 |
| 没连上却说"连接中断" | `onStopped` 不区分阶段 | 按 `wasConnected` 分别发「连接失败」/「连接中断」 |
| 直接抛 socket 英文原文 | `e.message` 原样上屏 | `friendlyError()` 分别映射：主机不可达 / 拒绝连接 / 超时 / 地址无法解析 / 连接被重置，各给一句能照做的建议；原文仍留在 logcat |

## 已知问题 / 遗留

- 每次连接前的发现要 ~3.5s（SSDP 2s + 网段扫描），期间「发现相机」显示"搜索中…"、连接会稍晚开始
- 相机同时只接受有限连接：上一轮 socket 未释放时立刻重连可能拿到 `EHOSTUNREACH`，等一下再点即可
- 仍未做 release 签名，产物为 debug 签名，仅适合自用与测试
