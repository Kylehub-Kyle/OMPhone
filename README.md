# OM Phone

![version](https://img.shields.io/badge/version-1.8-blue)
![platform](https://img.shields.io/badge/Android-8.0%2B-3ddc84?logo=android&logoColor=white)
![license](https://img.shields.io/badge/license-MIT-green)
![CI](https://github.com/Kylehub-Kyle/OMPhone/actions/workflows/android.yml/badge.svg)

把 OM Capture 的「连同一 WiFi 自动收图」搬到手机上。

App 连上相机后常驻监听，一按快门、录完视频，原文件就会自动落到手机的
`DCIM/OM Phone`，按卡槽与文件类型筛选，RAW / JPEG / MOV 都可原样保存。

> 非官方项目。与 OM Digital Solutions 无关，不使用其商标资源，仅通过相机开放的 PTP/IP 通道通信。

## 它解决什么

官方软件只在电脑上跑，拍完要回桌边插卡或等同步。OM Phone 让相机在户外连上手机热点就能落盘，
拍一张存一张，手机相册立刻可见。

| | OM Capture（PC） | OM Phone |
|---|---|---|
| 设备 | 电脑 | 手机（Android 8.0+） |
| 组网 | 同一 WiFi | 手机热点 / 同一路由器 |
| 收图 | 手动或自动 | 全自动，按类型筛选 |
| 预览 | 电脑端 | 横屏全屏，支持缩放、旋转、翻页 |

## 功能

- **自动收图**：事件驱动的即时下载，相机写盘未完成时自动等待重试
- **类型筛选**：卡槽 1 / 卡槽 2 各自独立勾选 `RAW` `JPEG` `MOV`
- **断线自愈**：相机休眠会断开事件通道，App 会显示「连接中断」并自动重连
- **文件名规则**：三段式（前缀 - 基本 - 后缀），支持日期、时间、连续号码、原始文件名
- **横屏看图**：全屏预览、双指缩放旋转、单指拖动、左右翻页，滑到两端有边界提示
- **深浅色主题**：跟随系统，预览底色同步变化

## 安装

**本仓库不提供预编译 APK。** 客户端 GUID 是相机白名单里的设备专属凭据，一份预编译包
只对构建它的那台相机有效，对别人没有意义，公开它还会泄露该凭据。所以请按
[从源码构建](#从源码构建) 生成自己的 APK：

1. 填好 `local.properties`（`sdk.dir` + `ptp.client.guid`）
2. `./gradlew assembleDebug`
3. 把 `app/build/outputs/apk/debug/app-debug.apk` 传到手机安装（需允许「安装未知来源应用」）
4. 首次打开授予通知权限（前台服务需要常驻通知）

最低 Android 8.0（API 26）。

## 使用

### 一、组网

**相机连手机热点（推荐，户外可用）**

1. 手机开「个人热点」，建议 5GHz
2. 相机：`菜单 → 网络 → Wi-Fi 设置`，连上该热点
3. 相机：`菜单 → 网络 → PC 连接` → 选 Wi-Fi
4. 相机屏幕出现 **Wi-Fi + PC 连接** 图标后，回到 App
5. App 打开即自动发现相机并把地址填进输入框；换过网络或发现不到时，点「发现相机」重新扫一次，
   也可以手动填入相机 IP（相机网络信息页里有）
6. 点「连接」（每次都先重新发现一遍，避免连到旧地址），状态变绿、显示 `OMSYSTEM OM-1 · 序列号` 后即开始监听

**同一路由器**：同上，省掉热点那一步。相机 IP 由路由器分配，形如 `192.168.1.50`。

> 相机同一时刻只允许一个 PTP 会话。电脑上开着 OM Capture、或插着 USB，手机就连不上，反之亦然。

### 二、竖屏：控制面板

- **相机连接**：打开即自动发现，地址不保存（相机换网就变，存下来只会连到旧地址）；连上后按钮变红「断开」
- **导出类型**：卡槽 1 / 卡槽 2 各三档，未勾选的类型只留在相机卡里
- **保存位置**：固定 `DCIM/OM Phone`；只有**文件名规则**可点进二级菜单
- **传输**：实时进度，失败会显示原因
- **底部**：等待数量 / 已收数量与总大小

### 三、文件命名

点「文件名规则」进入二级菜单，按三段式拼名，留空的一段自动省略：

| 选项 | 输出 |
|---|---|
| 无 | 不输出该段 |
| 原始文件名 | 相机里的文件名（去扩展名） |
| 自定义文字 | 任意字符串 |
| 拍摄日期 | `yyyyMMdd` |
| 拍摄时间 | `HHmmss` |
| 拍摄日期和时间 | 六种预设，如 `YYMMDD_HHMMSS` |
| 连续号码 | 起始数字 + 位数（补零），按收图顺序累加 |

扩展名跟着实际类型走（`.JPG` / `.ORF` / `.MOV`）。默认规则是
「拍摄日期 - 连续号码 - 原始文件名」，即 `20261117-0001-P1170500.JPG`。
规则存 `SharedPreferences`，重启不丢。

### 四、横屏：信息栏 + 全屏预览

横屏只有一条常驻信息栏，下面整块留给照片：

```
● 未连接 ▾ │ [RAW] P1170500.ORF [16.97 MB]    20 / 20  已收 20 · 275 MB  ⤢  ⚙  [连接]
```

- **连接状态**：点它弹出「连接相机」（发现 / 手动填 IP）
- **文件信息**：类型徽章 · 文件名 · 大小徽章
- **位置指示**：`第几张 / 共几张`，按拍摄顺序编号（最早 `1 / N`，最新 `N / N`）
- **收图统计**：已收个数与总大小；下载中显示 `下载 62%`
- **⤢** 用系统应用打开原图；**⚙** 导出格式 / 文件命名 / 断开连接
- 背景铺满顶边，内容按挖孔与屏幕圆角对称留白，照片紧贴信息栏下沿

**手势**（对标系统相册）

- 双指捏合：以两指中心为锚点缩放，1×–8×
- 双指旋转；放大后单指拖动平移，边界钳制
- 双击：以点击点为锚点放大到 2.6×，再双击复位
- 未放大时左右拖动翻页：照片跟手平移，不预览前后张；拖过 90dp 或甩动 ≥ 350dp/s 即切换
- 滑到头：橡皮筋效果 + 底部提示「已经是最后一张了 / 已经是第一张了」
- 有任何变换时底部浮出 `x.x× · 90° ｜ 复位` 胶囊，配色随身后亮度自适应

ORF 直接可看：优先用同批收到的同名 JPG，否则解析 ORF 内嵌 JPEG 预览，并按 TIFF 方向标记转正。
MOV 取首帧做封面。左右两张提前解码缓存，翻页不白屏。

**断开后**会清空相机型号、IP 与日志，状态回到「未连接」，不残留上次连接信息。

## 已知前提

- **会话独占**：相机一次只服务一个 PTP 客户端
- **休眠断连**：相机会自动休眠，建议把自动关机时间调长；App 会每 5–20 秒重连
- **热点隔离**：部分手机开热点时会禁止客户端互访，此时「发现相机」会失败，请手动填 IP
- **仅局域网**：PTP/IP 不加密，不要在不信任的网络上使用
- **需自备客户端 GUID**：源码不含该凭据，直接下载 Release 里的 APK 也无法连接你的相机

## 从源码构建

需要 JDK 17 + Android SDK 34。工程自带 Gradle Wrapper，无需本机安装 Gradle。

```bash
cp local.properties.example local.properties   # 然后按注释填写（该文件不会入库）
./gradlew assembleDebug                        # 产物：app/build/outputs/apk/debug/app-debug.apk
./gradlew testDebugUnitTest                    # 协议线级测试 + 命名规则单测
```

`local.properties` 需要两项：

| 键 | 说明 |
|---|---|
| `sdk.dir` | Android SDK 路径 |
| `ptp.client.guid` | 客户端 GUID，32 位十六进制。相机只接受白名单内的那一组，**仓库里没有这个值**，需自行提供；未填时构建产物能安装，但连接会直接提示「未配置客户端 GUID」 |

> 客户端 GUID 属于设备专属凭据，因此不随源码发布，也不打进 Release 的二进制。
> 想连自己的相机，必须用自己的值本地构建。

Windows 下用 `gradlew.bat`。CI（GitHub Actions）会跑同样的两条命令（用占位 GUID，只验证编译与单测）。

## 协议实现要点

实现依据来自对相机 PTP/IP 通道的行为观测，这里只保留落到代码里的结论，**不包含原始抓包**：

| 环节 | 关键点 |
|---|---|
| 建连 | 先取 `:1900/DeviceDescription.xml`（UPnP）唤醒 PC 连接，再连 15740 |
| GUID | InitCommand 需携带相机白名单认可的客户端 GUID，值不在仓库内（构建时注入） |
| OpenSession | 事务号必须为 `0`，且事件通道要先于它建立 |
| 0x94dd | 返回 `文件名\0 + uint32 大小 + uint32 0`（21 字节） |
| 0x94de | 需 5 个参数：(句柄, 偏移, 长度, 0, 0)，少一个即 `0x2002` |
| 0x94be | 必须带上行数据阶段 8 字节 `(1, 句柄)`，结束包类型 `0x0c` |
| 视频 | 事件到达时文件仍在刷盘，`0x94de` 回 `0x2019`，等 2s 重试 |

## 隐私

- 仓库不含任何抓包文件（`.pcapng`）、字节流日志或逆向过程记录，这些材料只留在本地
- 上报给相机的客户端名统一为 `OM Phone`，不暴露本机主机名
- **客户端 GUID 不进仓库**：它由 `local.properties` 在构建时注入，公开源码与 Release 产物都不含真实值
- 无服务端、无统计上报、无第三方网络库；照片全部写在本地 `DCIM/OM Phone`
- 提交 issue 时请给序列号与 IP 打码，不要附真实照片截图
